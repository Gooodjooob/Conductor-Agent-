# 项目工程经验

## 架构设计

先建立真实送达、交付、返工和审核的小闭环，再扩展成员与宿主。task、attempt、delivery、review分别建模；展示投影不与账本争夺状态写权。unknown先对账，不重放原执行。

## 角色设计

职责、成员身份、宿主和模型分开。指定开发者不等于实际observedAgent，reviewer不等于QA。主控制卡或验证工具错误需要单独归属，不全部转嫁worker。

## 功能设计

用户首先需要知道项目在哪里、谁在做、已交付什么、哪里受阻和下一步是什么。普通中文摘要与技术证据并存；进度比例不替代关键门禁。无变化刷新不重建DOM，保留滚动、焦点和弹窗。

## 技术实现

事务内复核、幂等冲突检查、终态保护、冻结输入和有界只读来源读取是可靠性基础。通知重试不能重新执行开发。测试工具本身需证明能够发现失败；SHA证明字节绑定，不证明语义正确。

## 成果沉淀

合同、源码、独立审核、运行证据与用户摘要分开保存，再以索引关联。减少重复卡与无关SHA耦合；派发前验证依赖、权限和预算。离线通过、真实接通和产品可用分别验收。
