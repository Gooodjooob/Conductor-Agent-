# 案例五：从页面原型到本机交付

> 关键词：启动时序 / 安装与恢复 / 不用等待掩盖问题

## 问题

页面能打开 ≠ 服务可用。真实交付还要求：异常拉起、health 检查、备份恢复、自然登录启动。此前遇到过两个具体问题：

1. macOS launchd 节流导致服务拉起失败
2. 首次启动等待时间不足，被误判为安装失败

## 关键动作

1. **依据实际启动时序修复**，而不是加长等待时间硬扛
2. 提供完整的交付物：App + 用户级 LaunchAgent + health 检查 + 日志 + 恢复说明
3. 分别审核「测试场景」与「剩余真实使用条件」，不合并结论

## 结果与证据

- A1：支持历史安装与指定运行场景的验证（516 项测试）
- W1、B1：**自然登录与完整验收未完成**的状态如实保留，未标记为已验收

⚠️ 「open 命令 exit 0」不等于物理双击验证通过。这两者在证据上是分开的。

## 取舍

**不靠无限等待掩盖时序问题。** launchd 节流是环境行为，加 sleep 只是把失败推迟到用户手里。选择按真实启动顺序修复，虽然耗时更多，但交付的是"用户拿去能用"而不是"演示时能跑"。

## 追问准备

| 追问 | 回答要点 |
|---|---|
| health 检查的是进程还是正确配置？ | 分开：进程存活是基础项，配置正确性通过启动后读回验证 |
| 备份哪些数据？ | 用户数据与配置（SQLite 账本 + 配置文件），不含缓存与日志 |
| 如何证明重启后读取的是同一数据源？ | 恢复说明中写明数据路径与校验方式，重启后读回对比 |
