# 表述边界与证据分级

> 核对日期：2026-10-16。本文件只做资料与代码的**静态核对**，不对运行环境、凭据、宿主连接或完整系统验收背书。
>
> 这份文档存在的目的：**防止把限定场景的结论说成全量上线。** 一个项目不同模块可以处于不同等级，不能合成「全部完成」。

## 表述等级（四档）

| 等级 | 含义 | 对外可用动词 |
|---|---|---|
| **历史真实验证** | 有真实宿主、UI 或本机安装报告；只对对应场景成立 | 完成某限定链路验证、完成某安装与恢复场景验证 |
| **实现可定位** | 代码或候选存在，真实使用范围需另核 | 实现、开发、形成模块，并补范围说明 |
| **正式设计与规则** | 设计或规范存在，不据此推导运行成功 | 设计、定义、建立规范 |
| **待核或未运行** | 入口、身份、隔离、使用或验收未闭合 | 不声明完成，或说明待验收 |

## 责任归属

- **主控**：负责审核、直接修复与范围裁定，不自动等同于独立 QA
- **worker 实现**、**架构与审核**、**主控直接修复**：分别说明，不合并为"我一个人写的"
- 不将不同轮次的测试计数相加（如 516 + 54 + 636）冒充全项目验证总量

## 维护规则

1. 新增经验记录：问题、实际动作、适用范围、来源、反例和验证范围

3. 项目正式验收通过时增加新证据，再更新表述；本文件不是运行状态权威
