# 架构与角色

Conductor 使用 Python 与 SQLite 实现本地控制核心，浏览器界面消费读模型。控制服务负责身份、项目权限、任务状态与审核；Adapter 负责宿主调用和真实接收证据；Runner 负责受控执行与回收；看板负责展示。

规划原文、规划快照、运行状态与执行事实分别处理。导入文档不自动产生真实任务或通过记录；历史交付的批准不能继承到新版本。

事件使用稳定ID去重。同ID不同内容拒绝，迟到和旧序号不回退当前状态。关键校验与写入在事务内完成；审核绑定当前交付，返工创建新轮次。

## 角色

| 角色 | 责任 |
|---|---|
| 主控 | 产品、拆卡、权限裁定与审核 |
| Dev | 在指定范围实现候选并交付 |
| QA | 独立复现、测试与证据记录 |
| Runner / Adapter | 启动与采集受控宿主事实 |
| 发布者 | 在独立授权下执行发布 |

指定成员、账本开发者和实际运行身份不同。QA不因发现缺陷而自动获得产品写权限；开发者不能签发可信审核。受信调用身份来自控制入口，不信任payload自报角色。

提示词不是OS沙箱；路径校验不等于运行时只能写这些路径。真实宿主的文件、凭据、工具、网络与进程边界必须另外验证。
